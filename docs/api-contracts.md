# Finovate API Contracts

This document defines the API contracts between the Flutter frontend and Node.js/Express backend. Use this as the **source of truth** for both projects.

---

## Base Configuration

### Server
- **Base URL:** `/api/v1`
- **Default Port:** 5001
- **Android Emulator:** `http://10.0.2.2:5001/api/v1`
- **Other Platforms:** `http://localhost:5001/api/v1`

### Authentication
All protected endpoints require a valid Supabase JWT token:
```
Authorization: Bearer <supabase_jwt_token>
```

### Common Headers
```
Content-Type: application/json
Authorization: Bearer <token>
X-Correlation-Id: <uuid>
```

The `X-Correlation-Id` is generated by the client for request tracing. Backend echoes it back in responses.

### Standard Response Format

**Success Response:**
```json
{
  "success": true,
  "data": { ... },
  "message": "Optional success message"
}
```

**Error Response:**
```json
{
  "success": false,
  "error": "Human-readable error message",
  "code": "ERROR_CODE",
  "correlationId": "uuid"
}
```

### Common Error Codes

| Code | HTTP Status | Description |
|------|-------------|-------------|
| `UNAUTHORIZED` | 401 | Invalid or missing auth token |
| `FORBIDDEN` | 403 | Valid token but insufficient permissions |
| `NOT_FOUND` | 404 | Resource not found |
| `VALIDATION_ERROR` | 400 | Invalid request data |
| `INTERNAL_ERROR` | 500 | Server error |
| `B3_NOT_CONNECTED` | 400 | User has not connected B3 account |
| `RATE_LIMITED` | 429 | Too many requests |
| `LIMIT_REACHED` | 400 | Daily prompt limit reached (Sofia) |

### Rate Limits
- **General:** 100 requests per 15 minutes
- **Chat/Sofia:** 20 requests per 15 minutes

GET    /api/v1/b3/status       - Check B3 connection status (auth)
DELETE /api/v1/b3/disconnect   - Disconnect B3 account + revoke at B3 (auth)
```

### B3 Authorization (Admin) ✅ IMPLEMENTED
```
GET /api/v1/b3/authorizations                      - List all authorized investors (auth)
GET /api/v1/b3/authorizations/check/:documentNumber - Check specific investor (auth)
```

### B3 Data APIs ✅ IMPLEMENTED
```
GET /api/v1/b3/position/:assetType/:documentNumber  - Get positions (auth)
GET /api/v1/b3/movement/:assetType/:documentNumber  - Get movements (auth)
GET /api/v1/b3/trading/:documentNumber              - Get buy/sell transactions (auth)
GET /api/v1/b3/investors                            - Sandbox investors list (auth)
GET /api/v1/b3/portfolio/:documentNumber            - Complete portfolio (auth)
```

**Asset types:** `derivatives`, `equities`, `treasury-bonds`, `fixed-income`, `securities-lending`, `all`

**Query params (required):** `referenceStartDate`, `referenceEndDate` (YYYY-MM-DD)
**Query params (optional):** `page`, `pageSize` (trading only)

**B3 API Mapping:**

| Our Endpoint | B3 API |
|--------------|--------|
| `/b3/position/:assetType/:doc` | `/api/position/v3/{assetType}/investors/{doc}` |
| `/b3/movement/:assetType/:doc` | `/api/movement/v2/{assetType}/investors/{doc}` |
| `/b3/trading/:doc` | `/api/assets-trading/v2/investors/{doc}` |
| `/b3/investors` | `/api/updated-product/v1/investors` |
| `/b3/authorizations` | `/api/authorization-investor/v1/authorizations/investors` |

**Note:** Waiting on B3 to register redirect URI before full OAuth testing.

**Field Descriptions:**

| Field | Type | Description |
|-------|------|-------------|
| `user.has_b3_connected` | boolean | `true` if B3 OAuth is completed. Use this to show/hide "Connect B3" banner |
| `portfolio` | object \| null | `null` when `has_b3_connected` is `false`. Contains total value and sync info when connected |
| `composicao` | object \| null | `null` when `has_b3_connected` is `false`. Contains asset allocation breakdown when connected |
| `featured_stocks` | array | Always 3 stocks. User's favorites first (in order added), remaining slots filled with top volume stocks. Empty array `[]` if data fetch fails |
| `indicators` | array | Market indicators (USD, EUR, SELIC). Empty array `[]` if data fetch fails |

**Featured Stocks Logic:**

| User Favorites | Result |
|----------------|--------|
| 0 favorites | 3 top volume stocks |
| 1 favorite | [favorite, top1, top2] |
| 2 favorites | [fav1, fav2, top1] |
| 3+ favorites | [fav1, fav2, fav3] (first 3 only) |

- Favorites are shown in the order they were added (most recent first)
- Top volume stocks exclude any tickers already in favorites (no duplicates)
- Stock data comes from brapi.dev with ETL fallback

**Implementation Notes:**
- Pulls user data from Supabase `users` table (`first_name`, `last_name`, `tax_id`, `created_at`)
- `has_b3_connected`: Only `true` if B3 OAuth is completed (controls "Connect B3" banner display)
- Portfolio data: In sandbox mode (`USE_B3_SANDBOX=true`), uses `tax_id` from DB even without OAuth
- **When `has_b3_connected: false`**: Both `portfolio` and `composicao` are `null` - frontend should use `has_b3_connected` flag to determine UI state
- **Market Overview:** Contains nested `ibov` + `portfolio` metrics per period
- **Rentabilidade:** Raw number (e.g., -3.81), frontend handles formatting
- **Risco:** Includes `level`, `label`, and `volatility` (raw annualized value, e.g., 0.28 = 28%)
- **Chart:** Nested inside each period, labels shared for IBOV (portfolio uses same x-axis)
- **Risk Calculation:** Based on annualized volatility (std dev of daily returns × √252). Thresholds: <15% = low, 15-25% = moderate, >25% = high
- **Portfolio metrics in periods:** `null` for MVP (progressive unlock based on days since connection)
- **Indicators:** USD and EUR have `change_percent` from daily movement. SELIC always has `change_percent: 0` and `trend: "stable"`

**Progressive Portfolio History Unlock (MVP):**

| Days Since B3 Connection | Available Portfolio Periods |
|--------------------------|----------------------------|
| 0-6 days | IBOV only, `portfolio: null` in all periods |
| 7+ days | Week portfolio data available |
| 30+ days | Week + Month available |
| 90+ days | Week + Month + 3 months available |
| 365+ days | All periods available |

**`history_available_at` field:** Only present when B3 is connected. Shows dates when each period will become available.

**Frontend Logic:**
- `portfolio: null` in period → Show "Histórico em construção" or just IBOV line in chart
- `history_available_at` → Can show "Rastreando desde [connected_at]" message
- `daily_change: null` → Show "--" until day 2 of tracking

### GET /api/v1/market/stocks ✅

Get stocks/FIIs with flexible querying for home screen, stocks tab, and favorites.

**Auth:** Required
**Status:** Real data from brapi.dev (primary), with ETL fallback (`prod_analytics.b3_prices_fracionario` for stocks, `prod_analytics.b3_prices_vista` for FIIs)

**Query Parameters (matches brapi.dev /api/quote/list exactly):**
| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `tickers` | string | - | Comma-separated tickers (e.g., "PETR4,VALE3"). For specific quotes |
| `search` | string | - | Search by ticker or name (partial match) |
| `type` | string | "stock" | Asset type: "stock", "fund" (FII), "bdr", "all" |
| `page` | number | 1 | Page number (1-indexed) |
| `limit` | number | 10 | Items per page (max: 50) |
| `sortBy` | string | "volume" | Sort field: "name", "close", "change", "change_abs", "volume", "market_cap_basic", "sector" |
| `sortOrder` | string | "desc" | Sort order: "asc", "desc" |
| `sector` | string | - | Filter by sector. See `/market/sectors` for valid values |

**Usage Patterns:**
```
# Home screen - specific tickers (defaults or user favorites)
GET /market/stocks?tickers=PETR4,VALE3,ITUB4

# Stocks tab - All (paginated)
GET /market/stocks?page=1&limit=7

# Stocks tab - Top Gainers
GET /market/stocks?sortBy=change&sortOrder=desc&limit=20

# Stocks tab - Top Losers
GET /market/stocks?sortBy=change&sortOrder=asc&limit=20

# FIIs tab (type=fund)
GET /market/stocks?type=fund&page=1&limit=7

# BDRs tab
GET /market/stocks?type=bdr&page=1&limit=7

# Filter by sector
GET /market/stocks?sector=Finance&limit=10

# Sort by market cap
GET /market/stocks?sortBy=market_cap_basic&sortOrder=desc&limit=10

# Sort by absolute change
GET /market/stocks?sortBy=change_abs&sortOrder=desc&limit=10

# Sort alphabetically by name
GET /market/stocks?sortBy=name&sortOrder=asc&limit=10

# Search within results
GET /market/stocks?search=petro&limit=10

### GET /api/v1/market/stocks/search ✅

Autocomplete search endpoint for fast typeahead suggestions. Searches both stocks and FIIs by ticker or company name.

**Auth:** Required
**Status:** Real data from brapi.dev (primary), with ETL fallback

**Query Parameters:**
| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `search` | string | - | Search query (1+ chars required) |
| `limit` | number | 10 | Max results (max: 20) |

**Usage:**
```
# User types "p" - only ticker prefix matches
GET /market/stocks/search?search=p

# User types "pe" - ticker prefix OR name contains
GET /market/stocks/search?search=pe&limit=5

# User types "petro" - matches PETR4 (Petrobras)
GET /market/stocks/search?search=petro

# User types "banco" - matches BBAS3, BBDC4, etc. by company name
GET /market/stocks/search?search=banco
```

**Response (200):**
```json
{
  "success": true,
  "data": {
    "suggestions": [
      {
        "ticker": "PETR4",
        "name": "Petrobras PN"
      },
      {
        "ticker": "PETR3",
        "name": "Petrobras ON"
      }
    ]
  }
}
```

**Response when no results (200):**
```json
{
  "success": true,
  "data": {
    "suggestions": []
  }
}
```

**Implementation Notes:**
- **Primary Source:** brapi.dev search via `/api/quote/list?search=` parameter (~400ms response time)
- **Fallback:** Internal ETL from `prod_analytics.b3_prices_vista` if brapi fails
- Fractional stocks (ending in "F") are filtered out
- Lightweight response - only ticker and name for fast autocomplete
- Frontend should debounce requests (300-500ms recommended)

## Phase 4: Sofia & User Endpoints ✅ IMPLEMENTED

### Architecture Note: Langfuse Integration

Sofia chat usage is tracked via **Langfuse** (hosted in the same Railway project). The backend queries Langfuse's Supabase database directly for usage stats instead of maintaining a separate `user_prompt_usage` table.

**Data Flow:**
```
Flutter App → Backend → Langflow → Langfuse (auto-tracked)
                ↓
        Backend queries Langfuse for usage stats
```

### Frontend Flow for Sofia Chat

```
1. User opens Sofia screen
   → GET /sofia/usage              (show "3 de 5 perguntas restantes")
   → GET /chat/sessions            (list previous conversations)

2. User sends first message (no session yet)
   → POST /chat/stream { "message": "O que é PETR4?" }
   ← SSE: {"event":"session","data":{"session_id":"uuid"}}  ← SAVE THIS!
   ← SSE: {"event":"token","data":{"chunk":"PETR4"}}
   ← SSE: {"event":"token","data":{"chunk":" é..."}}
   ← SSE: {"event":"end"}

3. User sends follow-up message (has session)
   → POST /chat/stream { "message": "E VALE3?", "session_id": "uuid" }
   ← SSE stream...

4. User taps previous conversation
   → GET /chat/sessions/:id/messages  (restore history)

5. User deletes conversation
   → DELETE /chat/sessions/:id
```

**Key Points:**
- First message: Don't pass `session_id` → backend auto-creates one
- Capture `session_id` from the first SSE event (`event: "session"`)
- Subsequent messages: Always pass `session_id` to continue conversation
- New conversation: Don't pass `session_id` → gets a new one

**Response (200) - Pro user:**
```json
{
  "success": true,
  "data": {
    "is_pro": true,
    "daily_limit": null,
    "used_today": 15,
    "remaining": null,
    "resets_at": null
  }
}
```

**Implementation Notes:**
- Query Langfuse: `SELECT COUNT(*) FROM traces WHERE user_id = ? AND DATE(timestamp) = CURRENT_DATE`
- `is_pro` determined by `subscription_tier` in backend `users` table
- `resets_at` is always midnight UTC of next day
- No tracking endpoint needed - Langfuse auto-tracks via Langflow integration
